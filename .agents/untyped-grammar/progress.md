## Observations for later phases

From the phase 0 review, left for P2.2 (the leaf rule implemented in one place). P2.2 resolved the first two: the resolver's field rule delegates to its node rule, and the translator no longer decides cardinality itself. These still hold:
- The public `SymbolResolver.isFieldRepeatableFromContext(String, String)` takes only a node id, and its Javadoc mentions neither multilingual fields nor the field-as-context rule. The translator no longer calls it.
- The `-Language` attribute field of a multilingual field (for example `BT-99-Lot-Language`) is typed as a scalar although it yields one value per language; `rules.efx` relies on that (R-DCS-FM2, `... satisfies BT-99-Lot-Language == $lg`), so it must not change silently.

From P1.1:
- Indicator field values translate to the bare node (`PathNode/IndicatorField`), with no conversion to a boolean. Comparisons and `in` work, because a general comparison casts the node, but whatever takes the effective boolean value or compares items with `eq` does not: `if BT-00-Indicator then …` holds when the field says `false`, and `sequence-equal`, `index-of`, `value-union`, `value-intersect` and `value-except` treat the field's values as strings, so `sequence-equal(BT-00-Repeatable-Indicator, [TRUE, FALSE])` is always false and `index-of(BT-00-Repeatable-Indicator, TRUE)` finds nothing (both checked with Saxon). The same on `develop` (`XPathScriptGenerator.composeFieldValueReference`). The new tests take late-bound booleans from iterator variables rather than lock this in. Outside the plan's scope: generated output is sacred.
- A duration field multiplied by a number is rejected although `P1D * 2` and `2 * P1D` translate: `BT-00-Duration * 2` is a syntax error or a type mismatch in every position, and `2 * BT-00-Duration` is a type mismatch on its own (ANTLR picks the numeric late-bound alternative) but translates inside a duration comparison (`2 * BT-00-Duration > P1D`, which is what the new test uses). A defect of the typed grammar that phase 3 removes; phase 3 should add both forms as tests. Since P2.3 both translate on their own, as values, and have tests; `BT-00-Duration * 2 > P1D` is still a syntax error.
- `+` and `-` between a date and a duration translate when both operands are references (`BT-00-StartDate + BT-00-Duration`, through the late-bound dispatcher) but are rejected otherwise (`2020-01-01Z + P1D` is a syntax error, `BT-00-StartDate + P1D` a type mismatch); the typed grammar offers only `add-duration` and `subtract-duration`. The corpus uses neither the operators nor the functions. Yannis decided the operators are part of the language (see Decisions). Since P2.3 the forms the typed grammar parses translate (`BT-00-StartDate + P1D`, `BT-00-Duration + BT-00-StartDate`); `2020-01-01Z + P1D`, `2020-01-01Z - P1D` and a date-plus-duration inside a comparison (`BT-00-StartDate + P3D > 2020-01-01Z`) are still syntax errors, for phase 3.
- EFX's duration is one type, but it translates to two XPath types that do not mix: `xs:dayTimeDuration` for days and weeks, `xs:yearMonthDuration` for months and years. Two consequences, pinned as they are by the P1.1 tests and the same on `develop`: `BT-00-Duration + P1D` (and `-`) raises a dynamic error when the field's unit is a year or a month, and `sequence-equal` on durations, which sorts both sequences, raises one as soon as a sequence holds both kinds (`Cannot compare xs:yearMonthDuration with xs:dayTimeDuration`, checked with Saxon). A question of the language's duration model, outside the plan's scope: generated output is sacred.
- The template translator's `exitShorthandFieldValueReferenceFromContextField` cannot run. The lexer emits `$value` only in TEMPLATE mode, where it parses as `contextFieldExpressionBlock` (tested); the grammar's other `$value` alternative, in `expressionBlock`, is reachable only from label blocks, whose LABEL mode never emits the token. Dead since `formattedExpressionBlock` took over `$value`; phase 3 can drop the alternative and its handler.

From P2.2:
- The value of an attribute field is rebuilt from the field's absolute path and the current context (`composeFieldValueReference(fieldId, path)` discards `path`), so a predicate, an absolute slash or a context override on an attribute field disappears from the XPath: `BT-00-Attribute[BT-00-Text == 'x'] == 'a'` gives `PathNode/TextField/@Attribute = 'a'`, and `/BT-00-Attribute` from `ND-SubNode` gives `../PathNode/TextField/@Attribute`. Fixing it changes translations, so it is outside the plan; P2.2 types these references by what was written, so `/BT-00-Attribute-In-Repeatable-Node == 'a'` from inside its node is now `FIELD_MAY_REPEAT`.
- The `FIELD_MAY_REPEAT` message for an absolute reference names the current context, although the reference is read from the root. P4.2 rewrites the message.

From P2.3:
- A field used as the index of a late-bound sequence is translated inside the sequence's own predicate, where the context item is a value, not a node: `BT-00-Text[BT-00-Number]` gives `(PathNode/TextField/normalize-space(text()))[PathNode/NumberField/number()]`, which Saxon rejects. From the phase 2 review:
